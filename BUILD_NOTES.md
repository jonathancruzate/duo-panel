## 3. Spec Deviations from `TECH-NOTES.md` (and `SPEC-ADDENDUM.md`)

1. **Framework-Only UI — Zero AndroidX Dependencies (`TECH-NOTES.md` #1 overrides `SPEC.md` line 45):**
   - Because `androidx.appcompat` is not in the PC's local Gradle cache, `app/build.gradle.kts` declares zero AndroidX dependencies (only `org.jetbrains.kotlin:kotlin-stdlib:2.2.10`).
   - All eight activities (`MainActivity`, `PickerActivity`, `CompanionPanelActivity`, `SoloTrampolineActivity`, `AnchorActivity`, `LaunchLabActivity`, `SettingsActivity`, `AboutActivity`) extend `android.app.Activity` directly and use framework widgets (`LinearLayout`, `GridLayout`, `ScrollView`, `TextClock`, `EditText`, `AlertDialog`) styled with Samsung One UI dark theme drawables and `OneUiViews.kt` (`#000000` true black background, `#17171A` 26dp rounded focus blocks, `#0381FE` One UI Blue accents).
   - Posture detection uses width metrics (`screenWidthDp >= 600 || smallestScreenWidthDp >= 600`) with a `TODO(WindowManager)` comment in `SoloLauncher.kt` rather than pulling in `androidx.window`.

2. **`ActivityOptions.setLaunchWindowingMode` Hidden API Handling (`TECH-NOTES.md` #2 overrides `SPEC.md` lines 19–21):**
   - `ActivityOptions.setLaunchWindowingMode(int)` is a hidden API and is absent from the public `android-36` SDK stubs; calling it directly will not compile.
   - **Primary split mechanism:** `SoloLauncher.kt` uses public Intent flags (`FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_MULTIPLE_TASK | Intent.FLAG_ACTIVITY_LAUNCH_ADJACENT | FLAG_LAUNCH_ADJACENT_TO_RECENT`).
   - **Guarded reflection fallback:** `SoloLauncher.tryCreateWindowingModeBundle(windowingMode)` looks up `ActivityOptions.class.getMethod("setLaunchWindowingMode", int.class)` inside a `try/catch` block using AOSP `WindowConfiguration` mode constants (`WINDOWING_MODE_SPLIT_SCREEN_PRIMARY = 3`, `WINDOWING_MODE_SPLIT_SCREEN_SECONDARY = 4`, `WINDOWING_MODE_FREEFORM = 5`). If reflection is blocked or throws at runtime, it silently falls through to pure Intent flags and never crashes.

3. **Explicit `FLAG_LAUNCH_ADJACENT_TO_RECENT = 0x00100000` Constant (`TECH-NOTES.md` #3 overrides `SPEC.md` line 19):**
   - `FLAG_ACTIVITY_LAUNCH_ADJACENT_TO_RECENT` is absent from the `android-36` `android.content.Intent` stubs (which expose `Intent.FLAG_ACTIVITY_LAUNCH_ADJACENT = 0x00001000`).
   - `SoloLauncher.kt` explicitly defines `const val FLAG_LAUNCH_ADJACENT_TO_RECENT: Int = 0x00100000` (the AOSP constant value) and ORs both `Intent.FLAG_ACTIVITY_LAUNCH_ADJACENT` (`0x00001000`) and `FLAG_LAUNCH_ADJACENT_TO_RECENT` (`0x00100000`) into `adjacentLaunchFlags()` (`0x18101000`).
   - `SoloLauncher.IS_PUBLIC_ADJACENT_DISTINCT` checks whether `Intent.FLAG_ACTIVITY_LAUNCH_ADJACENT != 0x00100000`, and `LaunchLabActivity` prints both constants, their distinctness, and the exact hex flag bits sent on every launch attempt.

4. **Public `ActivityOptions.setLaunchBounds(Rect)` in Strategy C (`TECH-NOTES.md` #4):**
   - `ActivityOptions.setLaunchBounds(Rect)` is public in `android-36`. `SoloLauncher.executeStrategyC` passes half-screen `Rect` bounds (left/right half in wide/landscape, top/bottom half in portrait) via `ActivityOptions.makeBasic().setLaunchBounds(bounds)` while leaving windowing mode default (never pairing `setLaunchBounds` with a split-screen windowing mode).

5. **Pinned AGP `9.1.1` + Kotlin `2.2.10` (`TECH-NOTES.md` #5):**
   - `settings.gradle.kts`, `build.gradle.kts`, and `app/build.gradle.kts` are pinned to AGP `9.1.1` and Kotlin `2.2.10` so the project resolves cleanly from the local Gradle cache.

6. **Flag-Based Variants for Strategies A & B + Left/Right Corner Shortcut Entry Points (`TECH-NOTES.md` #6 & `SPEC-ADDENDUM.md`):**
   - Because direct `setLaunchWindowingMode` calls are not public, Strategy A launches the target normally (`NEW_TASK | CLEAR_TOP`) followed by `PickerActivity` (or second app) with `adjacentLaunchFlags()`, while Strategy B launches the target itself with `adjacentLaunchFlags()` (+ guarded mode 3 reflection) followed by `PickerActivity` with `adjacentLaunchFlags()` (+ guarded mode 4 reflection). Both paths and their dedicated buttons are preserved in `LaunchLabActivity`.
   - Per `SPEC-ADDENDUM.md` (superseding the entry-point ordering in `SPEC.md`), `MainActivity` leads with **Add LEFT shortcut** (bottom-left corner) and **Add RIGHT shortcut** (bottom-right corner) opening the One UI styled `PickerActivity` (`launchPickedApp` / `reanchorPicker` via `AnchorActivity`), with per-app Solo and two-app Pair shortcuts right below.
