# DuoPanel 0.2.0 — Stage No-Duplication Audit

> **Settled Clock Directive — Confirmed Applied As Given**
> - **Stage fresh-entry & over-app states:** Exactly **one** clock renders by default — the **companion pane clock block** (`companionClockBlock`), controlled by its existing **Clock** toggle (`companionClockActionBtn`). The picker pane clock card (`pickerClockBlock`) and its top-bar `Clock` toggle (`pickerClockActionBtn`) are removed.
> - **0.2.0 after-pick state** (app frame on one half, app list/picker on the other): **No** big clock renders by default on either pane; the system status bar time is sufficient.
> - **Standalone `PickerActivity`:** Keeps its clock card unchanged (single-window, not a duplication case).
> - *(Note: `DESIGN-PASS-0.2.0.md` was not present in the project root; this audit is grounded directly in `StageActivity.kt`.)*

`buildAppBackdropPane()` (`:347-395`) renders a cropped screenshot bitmap (or a transparent fallback with a bottom `"Tap to return to the app"` caption when capture is denied/failed/timed out) and a full-pane tap listener calling `finish()`. `buildCompanionPane()` renders the single DuoPanel control surface beside it.

| Element | Where it appears | Verdict | Reason |
|---|---|---|---|

Keeping tap-to-dismiss on the app half preserves direct return to the underlying app. |
| **Return to fullscreen app (`Full` vs tap-to-dismiss)** | **App backdrop:** whole-pane tap returns to the underlying fullscreen app (`:352-363`)<br>**Companion:** `actionsRow` `"Full"` (`:1306`, `expandPairedFullscreen()`) | **Keep `"Full"` on Companion only when `pairedPackage != null`** *(hide when null)*; **keep tap-to-dismiss on App backdrop** | When `pairedPackage != null`, `"Full"` explicitly expands that tracked app fullscreen via `SoloLauncher`. ## 3. Note on 0.2.0 After-Pick State (App Frame + Picker Pane)

When 0.2.0 transitions to **app frame on one side + picker pane on the other** (no Companion pane):
- **Picker `topBar`:** Restore `Swap`, `Full`, and `Close` (since Companion is no longer on screen to host them), plus a quiet `"DuoPanel"` link or tappable title for settings. Keep `Clock` **omitted** and render **no** big clock block (per settled directive).
- **Picker `statusCard`:** No `pickerClockBlock` and no `pairedRow` (the active app is visibly rendered on the opposite half); keep only the pick-mode segmented control + `hintBannerText`.

## 4. Recommended Removals for 0.2.0 (`StageActivity.kt`)

1. **Remove `pickerClockBlock` (`:492-519`) and `pickerClockActionBtn` (`:481-486`)** from `buildPickerPane()`, along with the unused `pickerClockExpanded` state and its visibility toggle in `refreshPickerChrome()` *(settled directive)*.
2. **Remove `Swap`, `Full`, and `Close` from `buildPickerPane()`'s `topBar` (`:479-480`, `:487`) whenever Companion is present (fresh-entry)**; gate those three actions so they render on Picker only in the 0.2.0 after-pick state when no Companion pane is shown.
3. **Remove `PanelGraphicView` (`:428-435`) and the `"DuoPanel Stage • Tap title for settings"` subtitle (`:455-461`)** from `buildPickerPane()`'s `topBar` (Companion keeps its 38dp `PanelGraphicView` and blue `"DuoPanel"` settings link).
4. **Remove `pairedRow` (`:521-549`)** from `buildPickerPane()`'s `statusCard`.
5. **Hide `pickAppRow` (and its trailing divider, `:1268-1277`) on `buildCompanionPane()` when `!overApp` (fresh-entry)** — keep it only when `overApp == true`.
6. **Hide `otherRow` (and its trailing divider, `:1209-1266`) on `buildCompanionPane()` when `!overApp && pairedPackage.isNullOrBlank()`**, and when `!overApp && !pairedPackage.isNullOrBlank()` replace `"${side.oppositeTitle} • Active app"` with `"Last paired app"` so it does not mislabel the picker half.
7. **Hide Companion's `"Full"` button (`:1306`) when `pairedPackage.isNullOrBlank()`** (both fresh-entry and over-app) so it never renders as a dead-end toast.
8. *(Intra-pane cleanup)* **Hide `"Long-press app to star"` in Picker's `favHeader` (`:632-636`) when `favApps.isEmpty()`**, since the empty-state message directly below it (`:841`) already gives the same instruction.
