# DuoPanel PATCH 0.1.1C — the list lives on the panel the app opens on (2026-11-21, Jonathan's correction)

Applies on top of PATCH-0.1.1 and PATCH-0.1.1B. Same build: versionName "0.1.1", versionCode 2. No new permissions, no new dependencies, framework-only. Reuse the existing proven launch primitives (adjacent flags, the AnchorActivity re-anchor, replace-own-slot launches); do not invent new flag combinations.

## What Jonathan corrected (with screenshots of the current build)
The corner-shortcut picker currently opens SPANNED across both panels, and after a pick it moves to the opposite panel. That is not Duo behavior. On the Duo, the app list is on the panel the app is going to open on. New model:

- Tap the **Left** shortcut: the app list (PickerActivity) opens confined to the **LEFT** panel only. The RIGHT panel shows the new minimal **CompanionPanelActivity** surface.
- Tap the **Right** shortcut: PickerActivity opens confined to the **RIGHT** panel only. The LEFT panel shows CompanionPanelActivity.
- Picking an app in the Picker opens it **on the Picker's own panel, replacing the Picker** (this becomes the DEFAULT pick mode for the corner-shortcut flows). The companion stays on the other panel.
- CompanionPanelActivity is a small One UI-styled surface: DuoPanel header, live clock and date, the name of the app on the other panel if known, and buttons: **Pick app** (summons the Picker on THIS panel, replacing the companion, with this panel as its side), **Swap**, **Full**, **Home**, **Close**. Swap/Full/Home/Close behave like the same buttons in the Picker.
- The previous behavior (pick opens the app on the other panel, Picker stays) remains available as the alternate mode toggle in the Picker ("Open on other side"); it is no longer the default for corner-shortcut flows. The mode toggle labels stay "Open on other side" / "Replace this panel", with "Replace this panel" preselected for corner-shortcut flows.

## Implementation from proven primitives only
- LEFT shortcut flow: PickerActivity (fullscreen at first frame) immediately launches CompanionPanelActivity with the existing adjacent-launch flags (the RIGHT-flow primitive: caller stays primary/LEFT, companion lands RIGHT), exactly once per fresh shortcut open. Log `PANEL_PAIR_FORMED` side LEFT.
- RIGHT shortcut flow: PickerActivity launches CompanionPanelActivity as a normal NEW_TASK primary (LEFT-flow step 1 primitive), then the existing AnchorActivity re-anchor spawns a fresh PickerActivity adjacent on the RIGHT whose side is RIGHT and whose default mode is "Replace this panel"; the original Picker finishes. Companion remains LEFT. Log `PANEL_PAIR_FORMED` side RIGHT.
- Guard both formations so they only run on a fresh corner-shortcut open (dedicated intent extra, e.g. EXTRA_PANEL_ENTRY=LEFT/RIGHT), never when the Picker is already in multi-window, and never twice for one entry (instance flag). If formation fails, the Picker simply stays fullscreen and logs `PANEL_PAIR_FAILED` with the reason; the user can still pick apps.
- Pick app from the companion: CompanionPanelActivity starts PickerActivity with no adjacent flag and its own panel side as EXTRA_SIDE plus default mode "Replace this panel", then finishes (the proven replace-own-slot primitive: the Picker takes the companion's split slot).
- Solo shortcuts: when split engages and `pickerOnFreePanel` is true, the free panel now shows CompanionPanelActivity instead of the 0.1.1B auto-target Picker: LEFT solo = app primary + anchor-spawned companion on RIGHT; RIGHT solo = companion primary (normal launch) + anchor-spawned app... if that geometry is not achievable with the existing primitives, fall back to: app launched adjacent from a transient Picker that then swaps itself for the companion on its own panel. Keep it simple and log `SOLO_WITH_COMPANION`. The 0.1.1B EXTRA_AUTO_TARGET mechanism may be removed if unused. When `pickerOnFreePanel` is false, Solo behavior stays as in 0.1.0.
- PickerActivity header/hints must reflect the new default: for corner flows the hint reads "Next app opens on THIS panel" when "Replace this panel" is selected. Keep the existing header side label (it names the shortcut's panel).
- Manifest: register CompanionPanelActivity (exported=false, resizeableActivity=true, same theme/configChanges handling as PickerActivity).
