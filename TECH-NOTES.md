# DuoPanel — Tech notes from the first run's toolchain/API probe (2026-11-20, verified on the PC against the real android-36 SDK)

These override SPEC.md / SPEC-ADDENDUM.md implementation details where they conflict. The product design does not change.

1. **androidx.appcompat is NOT in the PC Gradle cache.** v1 uses framework classes only (android.app.Activity, framework widgets, no AndroidX at all). This is preferred: zero dependency-download risk at build time. If Google Maven is reachable and appcompat downloads cleanly that is acceptable too, but framework-only is the safe default, do not fight the cache.
2. **ActivityOptions.setLaunchWindowingMode is a hidden API** (not in the public SDK). Do NOT call it directly; it will not compile against android-36 stubs. Options:
   - Primary split mechanism = Intent flags only (the public recipe): to launch an activity into the adjacent split slot, add FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_MULTIPLE_TASK | LAUNCH_ADJACENT_TO_RECENT.
   - Guarded reflection fallback: try ActivityOptions.class.getMethod("setLaunchWindowingMode", int.class) inside try/catch and use it if present (values: SPLIT_SCREEN_PRIMARY=3, SECONDARY=4, FREEFORM=5 per WindowConfiguration in AOSP). Reflection failure must silently fall through to the next strategy, never crash. Note in code comments that hidden-API reflection may be blocked on some builds; that is exactly why it is a fallback, not the primary.
3. **FLAG_ACTIVITY_LAUNCH_ADJACENT_TO_RECENT constant is reportedly absent from the android-36 Intent stubs** (probe in PROGRESS.md step 0). Define our own in SoloLauncher: `const val FLAG_LAUNCH_ADJACENT_TO_RECENT = 0x00100000` (the long-standing AOSP value) and OR it into launch intents. Also check at compile time whether Intent.FLAG_ACTIVITY_LAUNCH_ADJACENT exists in the stubs and, if it is a distinct constant, log its value in Launch Lab. Launch Lab's log must print the exact flag bits used per attempt so the Fold8 hardware test shows what was actually sent.
4. **ActivityOptions.setLaunchBounds(Rect) IS public** — Strategy C (freeform half) uses it as specced, with windowing mode left default (do not pair bounds with any split call).
5. AGP in cache: AGP 9.1.1 + Kotlin 2.2.10 (AGP built-in Kotlin). Pin the build files to those versions so the build resolves from cache. Gradle 9.3.1 standalone, JDK 21, SDK platforms android-36/36.1, build-tools 36.0.0/36.1.0 are on the PC.
6. Because of note 2, SPEC strategies A and B collapse into flag-based variants: A = target normal, then Picker/second app with adjacent flags. B = target itself launched with adjacent flags + NEW_TASK + MULTIPLE_TASK when a split may already exist or a recent task is present, then Picker adjacent. Keep both code paths and their separate Launch Lab buttons; the hardware test decides which Samsung honors.
